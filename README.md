# Сметчик РК: тонкий skill для Claude и Codex

Клиентский навык для MCP сервера [smeta.nakasse.kz](https://smeta.nakasse.kz/). Нормативы, цены и подробные workflow-правила получает с MCP; доступ определяется вашей учётной записью портала.

[Скачать актуальный ZIP](https://github.com/beketkz-pixel/smetchik-client/releases/latest/download/smetchik-client.zip)

## Marketplace для Claude Code

В терминале:

```sh
claude plugin marketplace add beketkz-pixel/smetchik-client
claude plugin install smetchik@smetchik-client
```

В новой сессии используйте `/smetchik:smetchik`. Для входа MCP откройте `/mcp`, выберите сервер плагина smetchik и пройдите OAuth своей учёткой портала.
В `/plugin` → Marketplaces → smetchik-client можно включить Auto-update. После обновления выполните `/reload-plugins` или начните новую сессию.

## Marketplace для Codex

```sh
codex plugin marketplace add beketkz-pixel/smetchik-client
codex plugin add smetchik@smetchik-client
```

Затем откройте каталог Plugins в приложении, выберите источник «Сметчик РК» и установите smetchik. В версиях CLI с командой `plugin add` можно установить из терминала (см. `codex plugin add --help`). Войдите в подключение MCP своей учёткой портала через OAuth.

Обновление каталога: `codex plugin marketplace upgrade smetchik-client`. После обновления откройте новый чат; при необходимости перезапустите приложение.

Если ранее отдельно установлен такой же skill, отключите его отдельную копию после проверки плагина. Если MCP уже подключён вручную, не используйте одновременно два подключения к одному серверу: сначала проверьте новое, затем отключите лишнее в клиенте. Действующие доступы на портале автоматически не отзываются.

Один общий skill лежит в `plugins/smetchik/skills/smetchik`. Манифесты клиентов ссылаются на него; подробные правила остаются на MCP. ZIP ниже — альтернативный способ для обычного Claude и ручной установки, одновременно с плагином он не нужен.

## Claude Web / Desktop

1. Скачайте ZIP по ссылке выше.
2. Откройте Customize → Skills → + → Create skill → Upload a skill, загрузите ZIP целиком и включите smetchik.
3. Если Skills недоступны, проверьте Settings → Capabilities → Code execution and file creation.

[Официальная инструкция Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude).

## Codex

Распакуйте ZIP и поместите папку `smetchik` целиком в пользовательскую папку skills:

- Windows: `%USERPROFILE%\.agents\skills\smetchik\SKILL.md`
- macOS / Linux: `~/.agents/skills/smetchik/SKILL.md`

Сохраните подпапку `references`. Если навык уже установлен, обновите существующую папку, не создавая дубликат. Начните новый чат и выберите `$smetchik`; если навык не появился, перезапустите Codex. Старый вариант `AGENTS.md` дополнительно устанавливать не нужно.

[Официальная инструкция Codex](https://learn.chatgpt.com/docs/build-skills).

## Подключение MCP

ZIP навыка не содержит ключей и не подключает сервер автоматически; плагин включает адрес MCP, но требует вашей авторизации. В клиенте отдельно подключите удалённый MCP `https://smeta.nakasse.kz/mcp` через OAuth вашей учётки портала. Для уже работающего подключения повторный вход не нужен. Возможности подключения зависят от клиента и его версии.

## Проверка

Напишите агенту:

> Используй навык smetchik. Получи актуальные правила MCP через workflow, покажи мои документы и прочитай готовую расшифровку выбранного PDF. Новое распознавание не запускай.

## Обновления

Обновление правил на MCP не требует переустановки skill. Новый диалог получает правила через workflow; в продолжающемся диалоге обновления становятся доступны при проверке версии, а не поступают автоматически. Чтобы обновить сразу: «Проверь версию MCP workflow и обнови правила».

Сам установленный skill автоматически из GitHub не обновляется: новый ZIP нужен при изменении клиентского входа или способа вызова инструментов.

## Источник и состав

Это канал распространения существующего `mcp/client-skill`, а не второй источник правил. В ZIP только `smetchik/SKILL.md` и короткий `smetchik/references/context-rules.md`; общие правила повторно не читаются, если уже получены от сервера. Содержимое копируется из единого исходника проекта; изменения вносятся там и публикуются новым выпуском. Серверный код, нормативная база и документы клиентов сюда не входят.
